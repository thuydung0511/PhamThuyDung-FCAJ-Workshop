## Goal

Add an AI feature to CloudNote: click the **🔊 Read** button to listen to a note, with speech generated by **Amazon Polly**. The feature must follow the same authentication and ownership rules as the other routes.

## Context: choosing an AI service

The account is on the **Free account plan**. I did not upgrade to the Paid plan to avoid real costs, so I tried these services in turn:

| Service | Result |
|---------|--------|
| Amazon Bedrock (Nova Micro, Claude) in the Playground | Blocked: requires adding a payment method |
| Amazon Comprehend (Real-time analysis) | Blocked: requires adding a payment method |
| Amazon Translate (Real-time translation) | Blocked: redirected to the "Free account plan access limitations" page |
| Amazon Polly in the Console | Works: English sounds good (Standard engine, voice Joanna); Vietnamese is readable but the pronunciation is poor because Polly has no vi-VN voice |

→ I chose **Amazon Polly** and demoed with English notes. In parallel, I opened an **AWS Support** case requesting Bedrock access (Account and billing → Account Activation → Bedrock Allowlisting, severity low), following the Lab 000001 guide; the case is waiting for a response.

## Steps

### 1. Permissions

- **For the IAM user (Console use):** the user already had 10 managed policies, so inline policy `ConsoleTestPolly` (`polly:DescribeVoices`, `polly:SynthesizeSpeech`) and managed policy `AWSSupportAccess` were added to group `cloudnote-network-group`.
- **For Lambda (least privilege):** added inline policy `PollySynthesizeSpeech` to `LambdaNotesExecutionRole`, containing only the `polly:SynthesizeSpeech` action.

### 2. New route on API Gateway

1. On `notes-http-api`, add route `POST /notes/{noteId}/speak`.
2. Attach the existing JWT Authorizer ([5.5](../5.5-authentication/)).
3. Create a **new Lambda integration** to `notes-api` (payload 2.0, enable *Grant API Gateway permission to invoke your Lambda function*).
4. The `$default` stage auto-deploys.

### 3. Lambda: `speak_note` function

The function checks that the note belongs to the caller before calling Polly, and returns MP3 as base64:

```python
def speak_note(note_id, user_id):
    # Đọc ghi chú bằng Amazon Polly, trả về MP3 dạng base64.
    item = table.get_item(Key={"noteId": note_id}).get("Item")
    # Note không tồn tại hoặc không thuộc user -> 403 (giống PUT/DELETE,
    # không tiết lộ note của người khác có tồn tại hay không)
    if not item or item.get("userId") != user_id:
        return response(403, {"error": "forbidden"})

    text = f"{item.get('title', '')}. {item.get('content', '')}".strip()
    if not text:
        return response(400, {"error": "note is empty"})

    result = polly.synthesize_speech(
        Text=text[:3000],        # giới hạn độ dài: đúng giới hạn Polly, kiểm soát chi phí
        OutputFormat="mp3",
        VoiceId="Joanna",
        Engine="standard",
    )
    audio_b64 = base64.b64encode(result["AudioStream"].read()).decode("utf-8")
    return response(200, {"audio": audio_b64, "contentType": "audio/mpeg"})
```

In `lambda_handler`, the `/speak` branch is matched by `routeKey` and placed **before** the `POST` branch that creates notes:

```python
        # Route đọc ghi chú (Polly). PHẢI đặt trước nhánh "POST" bên dưới,
        # nếu không request này sẽ bị xử lý nhầm thành "tạo note mới".
        if event.get("routeKey") == "POST /notes/{noteId}/speak" and note_id:
            return speak_note(note_id, user_id)
```

Increased the `notes-api` **timeout** from 3 to 10 seconds.

### 4. Frontend: "🔊 Read" button

Each note gets a "🔊 Read" button (`noteId` is escaped with `esc()`). `speakNote` calls the API through `authFetch`, handles error codes, then plays the MP3; status messages use `textContent`, so no HTML is inserted:

```javascript
async function speakNote(noteId, btn) {
  const card = btn.closest(".card");
  const status = card.querySelector(".speak-status");
  const holder = card.querySelector(".speak-audio");
  btn.disabled = true;
  stopAudio();
  status.textContent = "Đang tạo giọng đọc..."; // textContent: không chèn HTML -> an toàn XSS
  try {
    const res = await authFetch(
      `${API_URL}/${encodeURIComponent(noteId)}/speak`,
      { method: "POST" },
    );
    if (res.status === 401) {
      status.textContent =
        "Phiên đăng nhập đã hết hạn. Hãy đăng xuất và đăng nhập lại.";
      return;
    }
    if (res.status === 403) {
      status.textContent = "Bạn không có quyền đọc ghi chú này.";
      return;
    }
    if (!res.ok) {
      status.textContent = `Không đọc được ghi chú (lỗi ${res.status}).`;
      return;
    }

    const data = await res.json();
    // Giải mã MP3 base64 -> Blob -> phát bằng thẻ <audio>
    const bytes = Uint8Array.from(atob(data.audio), (c) =>
      c.charCodeAt(0),
    );
    const blob = new Blob([bytes], {
      type: data.contentType || "audio/mpeg",
    });

    const audio = document.createElement("audio");
    audio.controls = true;
    audio.src = URL.createObjectURL(blob);
    audio.onended = () => {
      status.textContent = "Đã đọc xong.";
    };
    holder.appendChild(audio);
    currentAudio = audio;

    status.textContent = "Đang phát...";
    // Nếu trình duyệt chặn tự phát, người dùng bấm nút ▶ trên thanh audio
    audio.play().catch(() => {
      status.textContent = "Bấm ▶ để nghe.";
    });
  } catch (err) {
    status.textContent =
      "Không đọc được ghi chú. Kiểm tra kết nối rồi thử lại.";
    console.error(err);
  } finally {
    btn.disabled = false;
  }
}
```

## Issues and fixes

| Issue | Fix |
|-------|-----|
| Bedrock and Comprehend returned `ValidationException` / not authorized | A Free account plan limitation that cannot be fixed in the Console → not used; opened a Support case requesting Bedrock access |
| Translate redirected to the "Free account plan access limitations" page | A plan limitation; noted, no upgrade |
| `not authorized to perform: polly:DescribeVoices` | Added inline policy `ConsoleTestPolly` to the group |
| `not authorized to perform: support:DescribeSupportLevel` | Attached `AWSSupportAccess` to the group (without using root) |
| The API was not visible in API Gateway | The Console was in us-east-1 → switched back to ap-southeast-1 |
| The Create case button opened a chat instead of a form | New Support interface; describing the request in the chat opened the case form |
| Risk that `/speak` requests would be handled as "create note" (the `if method == "POST"` branch catches every POST) | Matched by `routeKey` and placed the `/speak` branch first |
| Risk of a 500 error when reusing the old integration (the invoke permission might be tied to the old routes) | Created a new integration and granted permission to API Gateway |
| Polly's Vietnamese pronunciation is poor | A service limitation (no vi-VN voice) → demoed in English |
| The first "another user's note" test was invalid (sent the placeholder text instead of a real noteId) | Took a real noteId from account A and retested with account B |
